Home delivery option, date and time-slot choices
Transportation and Urban Studio E
Dataset description | Prepared 10 November 2026

Context
-------
This case study examines how e-commerce customers trade off delivery fees, speed and scheduling flexibility. Customers choose next-day delivery, normal delivery, or scheduled delivery with a specified date and time slot. The data can be used to study willingness to pay for faster delivery and narrower time windows, and the potential for demand management in home delivery. [1, 2]

Data Collection
---------------
The stated-choice survey was conducted in Japan from 30 April to 14 May 2021 with Yamato Holdings. Invitations went to Kuroneko Members in the Tokyo, Osaka and Nagoya metropolitan areas. The original survey had 4,872 completed responses, with five tasks per respondent; the cleaned research sample in [1] had 19,860 tasks from 4,062 respondents.

The class file delivery_option_SP_sample.csv contains 2,000 sampled choice situations, 66 columns and 1,622 distinct customers (no). Each row records one complete choice, with task attributes in wide format. Customers contribute one to four rows in this subset; retain no for panel estimation and respondent-level train/test splits. The file has no explicit task identifier, so preserve the original row number as a local task key.

Alternatives and choice coding
------------------------------
Choice code | Meaning
1000 | Next-day delivery: delivery one day after ordering; no selected time slot.
2000 | Normal delivery: delivery within a stated date range; no selected time slot.
3000 + 10*d + s | Scheduled delivery: d = 2,...,8 days after ordering; s = 1 earliest, 2 other/daytime, 3 latest slot. Example: 3051 means day 5, earliest slot.

The model in [1] groups the original time slots into three categories, giving 23 alternatives: two unscheduled options plus 7 days x 3 scheduled slot categories. The "other" category pools intermediate slots; it is not always a single physical time window. The survey delivery period is 09:00-21:00, with slots of 2, 3 or 4 hours.

Variables: task attributes and outcomes
---------------------------------------
All monetary delivery attributes are in Japanese yen. A suffix d denotes a day after ordering. Names and capitalization match the CSV.

Name | Description / coding
no | Customer identifier; repeated across sampled tasks.
sp_price_next /; sp_price_normal /; sp_price_specific | Base delivery fee for next-day / normal / scheduled delivery, respectively. Each takes values 300, 400, 500 or 600 JPY.
sp_add_weekend | Additional charge for scheduled delivery on a holiday: 0 or 100 JPY. The paper refers to holidays, not only weekends.
sp_add_night | Additional charge for the latest scheduled time slot: 0 or 100 JPY.
sp_slot_range | Width of each scheduled time slot: 2, 3 or 4 hours.
sp_day_after /; sp_day_range | Earliest normal-delivery day (2 or 3 days after ordering) / width of the normal-delivery date range (2, 3 or 4 days).
norm_day_mean | Normal-delivery mean time, in days. In all local rows it equals sp_day_after + sp_day_range / 2.
holiday1 to holiday8 | Holiday indicators for each of the next eight days (1 = holiday, 0 otherwise). The survey period includes Golden Week.
weekday2 to weekday8 | Day-of-week codes for days 2-8, stored as 0-6. The local codebook does not explicitly define the labels; confirm the convention before attaching weekday names.
Choice | Combined delivery-option/date/slot outcome; see the code table on page 1.
sp_choice | Original option/date outcome: 100 = next-day; 200 = normal; 302-308 = scheduled delivery on days 2-8.
sp_choice_slot | Original time-slot category, 1-13 for scheduled delivery; 1000 when no slot is selected. Exact clock-time labels are not supplied in the local codebook.
sp_choice_date_after | Selected day after ordering (2-8); 1000 for next-day/normal choices where the scheduled date question does not apply.
sp_choice_date_holiday | Stored holiday flag for the selected date. It disagrees with the corresponding holidayd field in 492 of the 700 scheduled choices; see preparation notes.
sp_choice_first_slot /; sp_choice_last_slot /; sp_choice_other_slot | Indicators of the chosen earliest / latest / intermediate slot. All are zero for next-day and normal delivery.
sp_slot_choice | Grouped selected slot: 1 earliest, 2 intermediate, 3 latest; 0 for next-day/normal delivery.

Outcome-derived fields describe the chosen alternative. When constructing utility functions, use the fee, day and slot attributes of every candidate alternative; selected-slot and selected-day flags are not exogenous predictors.

Preparation notes
-----------------
Use the full Choice code for the 23-alternative model, or explicitly aggregate it to three delivery options for a simpler model. The data contain 1,300 structural values of 1000 in the scheduled-date and original-slot fields. These are not delivery times or ordinary missing responses.

For scheduled alternative (d, s), the intended fee is sp_price_specific + sp_add_weekend x holidayd + sp_add_night x I(s = 3). Validate the calendar flags before applying this rule: the selected-date holiday flag is inconsistent with the day-specific flags. Do not silently overwrite the source data.

Possible analyses
-----------------
A three-option multinomial logit provides an initial comparison of delivery services. A richer model uses the 23 coded alternatives to estimate fee, waiting-time and slot-width effects, with shared components for service types or days. Repeated observations permit panel or mixed-logit specifications. State clearly whether the intermediate-slot category represents an aggregate of several original slots.
